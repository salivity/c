How Compilers Safely Reorder Assembly in C

Instruction scheduling is a compiler optimization technique that rearranges assembly instructions to maximize CPU instruction-level parallelism and avoid pipeline stalls without altering the program's observable behavior. During the compilation of C code, the compiler translates high-level statements into low-level operations and reorders them based on target hardware latencies and execution units. To guarantee safety, the compiler constructs dependency graphs that enforce strict rules around data dependencies, memory aliasing, sequence points, and hardware side effects.

Data Dependency Analysis

The primary safeguard against invalid instruction reordering is data dependency tracking. Compilers analyze assembly-level operations to identify three fundamental hazards:

  1. Read-After-Write (RAW / True Dependency): An instruction depends on the result of a preceding instruction. Reordering is prohibited because the second instruction must read the newly updated value.
  2. Write-After-Read (WAR / Anti-Dependency): An instruction overwrites a register or memory location that a prior instruction still needs to read. Reordering is safe only if register renaming or alternative storage eliminates the conflict.
  3. Write-After-Write (WAW / Output Dependency): Two instructions write to the same destination. The final write must remain last so subsequent reads receive the correct state.

The compiler represents these relationships as a Directed Acyclic Graph (DAG). Nodes in the DAG represent individual instructions, and edges define dependency constraints paired with minimum latency cycles. A node cannot be scheduled until all of its predecessor nodes have completed execution.

Memory Aliasing and Pointer Analysis

In C, memory accesses introduce ambiguity because multiple pointers can reference the same address. If the compiler cannot prove that two memory references point to distinct locations, it must assume they alias.

To safely reorder memory loads and stores, the compiler utilizes:

  • Type-Based Alias Analysis (TBAA): Governed by C strict aliasing rules, the compiler assumes that pointers of incompatible types do not reference the same memory location.
  • The restrict Qualifier: Declaring a pointer with restrict guarantees to the compiler that the pointer provides exclusive access to that memory block within its scope, unlocking aggressive reordering.
  • Conservative Scheduling Barriers: When pointer targets are unknown, stores act as barriers to subsequent loads from unidentified addresses, preventing the compiler from moving a read before an unresolved write.

Control Flow and Speculative Execution

Instruction scheduling typically occurs within basic blocks—linear sequences of code with a single entry and single exit. Reordering instructions across branches requires speculative execution checks. A compiler cannot hoist an instruction above a conditional branch if that instruction could trigger an observable exception, such as a null pointer dereference or division by zero, before the condition is evaluated.

Handling volatile, Sequence Points, and Barriers

The C standard dictates specific observable behaviors that instruction schedulers must preserve:

  • The volatile Keyword: Reads and writes to volatile variables represent observable side effects. The compiler cannot eliminate, combine, or reorder volatile accesses relative to one another or across sequence points.
  • Inline Assembly and Clobbers: Inline assembly blocks marked with __volatile__ or containing memory clobbers force the scheduler to treat them as scheduling fences. Instructions cannot move across these boundaries if they touch clobbered registers or memory.
  • Atomic Operations and Memory Fences: Under the C11 memory model, atomic operations with specific memory orderings (such as memory_order_acquire or memory_order_release) insert constraints that prevent the scheduler from moving surrounding loads and stores across the synchronization boundary.

The Scheduling Pass

Once dependencies, aliasing constraints, and hardware restrictions are captured in the DAG, the compiler runs a scheduling algorithm—most commonly list scheduling. The scheduler maintains a pool of "ready" instructions whose dependencies are fully resolved. It uses heuristics, such as critical path length and resource availability, to select the best instruction for the next cycle. Because the algorithm only selects from nodes with satisfied dependencies, the emitted assembly code achieves optimal execution speed while remaining strictly faithful to the semantics of the original C source.
