How C99 restrict Keyword Aids Compiler Optimization

The restrict keyword, introduced in the C99 standard, is a pointer qualifier that informs the compiler that a given pointer is the sole reference to a specific memory block within its scope. By explicitly guaranteeing that no other pointer will access or modify the same memory location during the pointer's lifetime, developers eliminate the issue of pointer aliasing. This guarantee allows the compiler to perform aggressive optimizations—such as caching values in CPU registers, reordering memory operations, and vectorizing loops—that would otherwise be unsafe.

The Problem of Pointer Aliasing

In standard C, the compiler must assume that any two pointers of the same type might point to the exact same location in memory—a situation known as pointer aliasing. Because of this possibility, the compiler must adopt a conservative optimization strategy.

Consider a simple function without restrict:

void update_values(int *a, int *b, int *val) {
    *a += *val;
    *b += *val;
}

In this scenario, the compiler cannot be certain whether a or b points to the same memory address as val. If a and val alias each other, the modification to *a also modifies *val. Consequently, the generated assembly must reload the value of *val from memory after modifying *a, resulting in redundant memory read operations and stalled execution pipelines.

How the restrict Keyword Solves Aliasing

Applying the restrict qualifier creates a formal contract between the developer and the compiler:

void update_values(int *restrict a, int *restrict b, int *restrict val) {
    *a += *val;
    *b += *val;
}

By marking these pointers with restrict, you guarantee that within the execution of update_values, the object referenced by val is not accessed through a, b, or any other pointer. The compiler now knows that modifying *a cannot alter *val.

Key Compiler Optimizations Enabled by restrict

Once the uncertainty of aliasing is removed, modern compilers (such as GCC, Clang, and MSVC) can unlock several performance enhancements:

1. Load Elimination and Register Caching

Because the compiler knows *val will not change during the execution of the function, it loads the value of *val into a high-speed CPU register once. It can then reuse that register for both additions rather than fetching the value from memory multiple times.

2. Instruction Scheduling and Reordering

Modern CPUs execute instructions out of order to maximize throughput. When pointers might alias, read and write operations must strictly maintain their program order to prevent stale reads. With restrict, the compiler is free to interleave, reorder, or group read and write instructions to best utilize the processor's execution units.

3. Loop Vectorization (SIMD)

Loop vectorization allows a CPU to process multiple data points concurrently using Single Instruction, Multiple Data (SIMD) instructions (such as AVX or ARM NEON). If arrays passed into a loop might overlap, the compiler cannot safely vectorize the loop, as an operation in one iteration might overwrite data needed for a subsequent iteration. Declaring array pointers as restrict confirms that memory regions do not overlap, allowing auto-vectorization passes to execute successfully.

Developer Responsibility and Undefined Behavior

The restrict keyword does not alter the generated machine code directly; rather, it alters the compiler's assumptions. If a programmer applies restrict to pointers that actually overlap in memory, the code violates the contract, resulting in undefined behavior. The compiler may produce code that generates corrupted data or subtle logic bugs, making it critical to use the qualifier only when non-overlapping access is guaranteed.
