Object-Like vs Function-Like Macros in C

In the C programming language, the preprocessor provides macros to perform textual substitutions before compilation begins. These macros are divided into two distinct categories: object-like macros and function-like macros. While object-like macros replace a single identifier with a defined code snippet or constant value, function-like macros accept arguments and emulate the syntax of a C function call. Understanding the operational and behavioral differences between them is essential for writing safe, maintainable, and predictable C programs.

Object-Like Macros

An object-like macro is a simple identifier that the preprocessor replaces with a defined replacement list (tokens or values). It takes no arguments and is most commonly used to define symbolic constants, configure platform-dependent code, or replace magic numbers.

#define BUFFER_SIZE 1024
#define PI 3.14159

When the preprocessor scans the source code, every independent occurrence of BUFFER_SIZE is directly replaced with 1024. Because it does not accept input parameters, its behavior is strictly static text substitution.

Function-Like Macros

A function-like macro looks and acts syntactically like a function call. It is defined with parentheses immediately following the macro name, enclosing a comma-separated list of formal parameters.

#define SQUARE(x) ((x) * (x))
#define MAX(a, b) (((a) > (b)) ? (a) : (b))

During preprocessing, the macro name and its parenthesized argument list are replaced with the replacement list, with every occurrence of the parameter replaced by the corresponding argument provided in the call.

Note on Definition Syntax: In a function-like macro definition, there must be no whitespace between the macro identifier and the opening parenthesis (. If a space is inserted (e.g., #define SQUARE (x) ...), the preprocessor interprets it as an object-like macro where the replacement text starts with (x).

Key Differences

1. Parameter Handling

  • Object-Like: Accepts no parameters. It performs a direct, identical replacement across all instances.
  • Function-Like: Accepts zero or more arguments, allowing the macro to generate customized code based on the inputs provided at each call site.

2. Invocation Syntax

  • Object-Like: Invoked simply by using its name as an identifier (e.g., int size = BUFFER_SIZE;).
  • Function-Like: Requires parentheses enclosing the expected number of arguments (e.g., int area = SQUARE(5);).

3. Side Effects and Safety Risks

  • Object-Like: Rarely causes unexpected side effects beyond standard operator precedence issues if expressions are defined without enclosing parentheses.
  • Function-Like: Poses significant risks when arguments contain side effects (such as increment or decrement operators). For example, invoking SQUARE(i++) expands to ((i++) * (i++)), causing undefined behavior or evaluating the increment operation multiple times.

4. Type Safety and Scope

Neither macro type enforces type checking because the preprocessor operates strictly on text tokens before the compiler checks types. However, function-like macros can accept arguments of any type compatible with the replacement expression, acting similarly to generic functions, whereas object-like macros replace fixed tokens.

Summary of Differences

Feature Object-Like Macro Function-Like Macro
Arguments None Accepts parameters
Syntax #define NAME replacement #define NAME(args) replacement
Spacing Constraint Space after name is optional No space between name and (
