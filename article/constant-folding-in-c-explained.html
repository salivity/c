Constant Folding in C Explained

Constant folding is a compiler optimization technique that simplifies mathematical expressions containing fixed, immutable values during compilation rather than deferring their execution to runtime. By computing values such as arithmetic operations, bitwise manipulations, and literal evaluations before generating machine code, the C compiler eliminates redundant runtime CPU instructions, decreases executable size, and enables further downstream optimizations without sacrificing code readability.

How the Compiler Identifies Constant Expressions

During the front-end phase of compilation, the C compiler parses source code into an Abstract Syntax Tree (AST). The AST represents the hierarchical syntactic structure of the program, where operators (such as +, -, *, /) form parent nodes and operands form child nodes.

The compiler traverses this tree to determine if the operands attached to an operator are compile-time constants. An expression qualifies for constant folding if its inputs consist exclusively of:

  • Integer, character, or floating-point literals (e.g., 5, 'a', 3.14).
  • Enumeration constants.
  • Results of the sizeof or _Alignof operators.
  • Preprocessor macros that expand directly into literals.

The Evaluation Mechanism

Once an expression is verified as constant, the compiler evaluates it using the following steps:

  1. Tree Traversal: The compiler performs a post-order traversal on the AST. It evaluates the deepest leaf nodes first, ensuring that nested operations (e.g., (2 + 3) * (4 + 1)) are resolved inside-out.
  2. Target-Aware Emulation: The compiler computes the result using its own internal arithmetic routines. To maintain correctness, it executes this math according to the data types, sign representations, bit widths, and endianness of the target platform, rather than the host system compiling the code.
  3. Node Replacement: The operator node and its child operand nodes are removed from the AST and replaced by a single terminal node containing the final evaluated literal.
  4. Machine Code Emission: When the back-end generates assembly or machine code, it outputs only the folded value as an immediate operand, completely skipping arithmetic instructions like ADD or MUL.

Code Example

Consider the following variable definition in C:

int seconds_in_day = 60 * 60 * 24;

Without constant folding, the generated machine code would load 60, multiply it by 60, and then multiply the result by 24 every time the statement executed. With constant folding, the compiler computes 60 * 60 * 24 = 86400 during compilation, transforming the intermediate representation into:

int seconds_in_day = 86400;

Relationship with Constant Propagation

Constant folding often operates in tandem with constant propagation. If a variable is assigned a known constant and is never modified, the compiler replaces subsequent occurrences of that variable with the constant value, which can trigger additional constant folding passes:

const int width = 10;
const int height = 20;
int area = width * height; // Propagates 10 and 20, then folds to 200

Constraints and Boundary Conditions

Compilers must adhere to the C standard when executing compile-time arithmetic:

  • Undefined Behavior: If a constant expression results in undefined behavior—such as division by zero (5 / 0) or signed integer overflow—the compiler issues a warning or error and halts folding.
  • Floating-Point Precision: Floating-point operations require strict adherence to IEEE 754 standards. If compile-time rounding or dynamic environment flags (such as rounding modes or floating-point status flags) could alter the result, conservative compiler flags may prevent folding to ensure standard compliance.
